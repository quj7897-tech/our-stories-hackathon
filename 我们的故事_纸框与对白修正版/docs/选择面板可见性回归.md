# 自动播放后的选择面板可见性

2026-10-25。用户报告早晨厨房场景后停住。

## 实际复现

自动播放到一次选择后果结束时，`#choices`已有`show`，继续按钮也已解除hidden，但浏览器读取到：

```json
{"opacity":"0","playState":"paused","stage":"stage motion-paused"}
```

根因是`art-motion.css`对暂停舞台的所有后代强制暂停动画，把选择、反馈及复盘的fadein停在透明起点。手动跳过演出直接触发完成回调时不一定执行同一轮时钟同步，因此此前手动路径检查漏掉了这个问题。

## 修正与本次验证

移除暂停所有后代的规则。人物由剧情时钟暂停，背景及其他演出动画继续由syncDecorations控制；UI淡入保持独立。

按相同路径让发送反馈自动播完，浏览器读到：

```json
{"opacity":"1","playState":"running","stage":"stage motion-paused"}
```

反馈面板实际可见；点击继续故事进入第八场。8项播放器和全天剧情测试通过。截图：artifacts/choice-freeze-before.png与choice-freeze-fixed.png。

后续验收必须包含“让最后一个节拍自然播完后查看面板”，不能只依赖手动连点、DOM存在或节点状态正确。
